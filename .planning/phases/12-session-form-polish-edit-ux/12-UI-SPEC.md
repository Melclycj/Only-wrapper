## Spacing Scale

The form geometry MUST be expressed with the `--space-*` tokens. The current form CSS (`terminal.css` L378–489) carries several pre-token one-off literals (4 / 8 / 10 / 12 / 16 px) that already align to the scale and a few odd-balls (22px dialog top-pad, 2px restart-group bottom-pad) — snap these to the nearest formal scale step during the ui-lab polish loop (Discretion). New geometry uses the formal scale only.

**Formal Spacing Scale (4-multiple steps ONLY):**

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| `--space-1` | 4px | Label-to-input micro gap; emoji-grid cell gap |
| `--space-2` | 8px | Color-swatch row gap; field internal padding rhythm; cwd ↔ Browse… gap; modal-actions button gap; picker section gaps |
| `--space-3` | 12px | **Inter-field vertical rhythm within a group** (`.edit-field` margin-bottom); group inner padding; input vertical padding |
| `--space-4` | 16px | Input horizontal padding rhythm; default block spacing |
| `--space-5` | 20px | **Inter-GROUP spacing** (Identity group ↔ Launch group); dialog inner padding rhythm |
| `--space-6` | 24px | Dialog outer padding; major vertical break above the section subhead |

**8-point compliance:** Every value in the formal scale is a multiple of 4 (canonical 4/8/16/24 steps present as `--space-1`/`--space-2`/`--space-4`/`--space-6`, with 12/20 px on-scale intermediates). The contract declares ONLY these clean steps for the form surface.

**Legacy note (NOT canonical design steps):** `tokens.css` also exposes `--space-1_5` (6px) and `--space-2_5` (10px). These are **pre-existing migration aliases** carried from shipped form geometry — they are not part of this surface's spacing contract. Where the shipped form currently renders a 6px swatch gap or 10px input vertical padding, the form polish **SNAPS to the nearest clean step (8 or 12)** during the ui-lab loop. 6px/10px are NOT introduced as canonical design steps for this surface.

**Exceptions (element dimensions, not spacing-scale steps):**
- Dialog width `min(460px, calc(100vw - 48px))` is a layout dimension, not a spacing step — keep (small-laptop-friendly single column, D-02).
- Emoji-cell tile (~`aspect-ratio 1/1`, grid cell) and color-swatch (~26px) are sized elements, not spacing gaps — retune to a token-expressible size during the picker polish (Discretion D-03).
- 999px pill radius (none used in the form today) stays literal if introduced — a full-round shape, not a scale step.

## Typography

Form typography is composed from `--font-ui` (Nunito) only. The set below is value-preserving from the existing form block (`terminal.css` L170–489), retuned only where the two-group restructure (D-02) and the validation line (D-04) need it. **Two weights total: 400 (regular) and 700 (bold)** — matching the loaded Nunito faces. (The shipped form uses 600 for labels/buttons; this contract promotes those to 700 to hold the two-weight discipline the Phase-10 UI-SPEC locked, OR keeps 600 only if the ui-lab pass shows 700 reads too heavy for the 12px label — 600 is then the single permitted alternative for that one role. No third *distinct* weight is introduced beyond 400 + the bold step.)

**Type scale — 3 distinct font sizes (12 / 14 / 17px).** `tokens.css` does not expose `--font-size-*` / `--text-*` tokens today (sizes are CSS literals in the form CSS), so the consolidated role set is declared explicitly. Hierarchy is carried by **size + weight + case**, not by 1px size deltas:

| Role | Size | Weight | Line Height | Where |
|------|------|--------|-------------|-------|
| Dialog title | 17px | 700 | 1.2 | `.modal-title` — "Edit session" |
| Section subhead | 12px | 700 | 1 | NEW — the two group headers ("Identity", "Launch") + the existing `.applies-on-restart-hint`. Differentiated from the field label (same 12px) by `text-transform: uppercase` + letter-spacing (`0.02em`) + `--color-faint`/`--ink-faint` — NOT by a unique size |
| Field label | 12px | 700 | 1.2 | `.edit-label` — persistent, above each field (NOT placeholder-only); soft ink, no uppercase |
| Input / select text | 14px | 400 | 1.3 | `.edit-input` / `.edit-select` / `.emoji-input` — the user's typed value |
| Button text | 14px | 700 | 1 | `.modal-btn` (Save / Cancel) + `.edit-browse-button`. Shares the 14px input size; differentiated from input text by weight 700 |
| Validation helper | 12px | 400 | 1.3 | NEW — inline hint/error text under a field. Shares the 12px label size; differentiated by weight 400 + tone (`--ink-faint` for a hint, `--color-danger` for a genuine error — D-04) |

**Distinct-size count = 3 (12 / 14 / 17px).** The 12px size carries three roles (section subhead, field label, validation helper) separated by case/weight/tone; the 14px size carries two roles (input text @400, button text @700). This holds a real ≥2px hierarchy between every adjacent size step rather than a 1px-apart cluster.

**Line-height policy:** body/label text runs tight (1.2–1.3, calm chrome — DESIGN.md north star, not the generic 1.5 web default). Single-line glyph rows (section subheads, buttons) use 1 to avoid baseline jitter (existing Pitfall-6 guard). Inputs keep a comfortable 1.3 so a long cwd path stays legible.

**Discretion (CONTEXT):** Exact section-subhead styling (uppercase + tracking amount) and the label weight (600 vs 700) are tuned in the ui-lab look→edit→re-look loop against `DESIGN-RUBRIC.md §edit-modal` line "Fields: labeled clearly in soft ink."

## Color

The form palette is the LOCKED Switchboard token set (warm low-contrast chrome). Calm by default; **`--color-danger` red is spent ONLY on a genuine validation error** (empty-name fallback hint stays neutral `--ink-faint`; the red appears only when main rejects or a field is invalid). All values are `var()` references — no literals (guarded by `tokens-completeness.test.ts`).

| Role | Value (token) | Usage |
|------|---------------|-------|
| Dominant (60%) | `--surface` = `#ffffff` | The dialog card body — the form sits on a white card |
| Backdrop / recessed (the screened ground) | `--bg-sunk` = `oklch(0.955 0.01 85)` + `.modal-overlay` scrim | The dimmed backdrop behind the dialog; the recessed "Launch" group surface; input hover/active wash |
| Secondary structure (30%) | `--line` / `--line-soft` borders | Input borders, hairline group dividers, the dashed/grouped "Launch" container, emoji-cell + swatch outlines |
| Accent (10%) | `--color-accent` = `oklch(0.62 0.14 248)` (brand blue) | See reserved list below |
| Destructive | `--color-danger` = `oklch(0.58 0.16 25)` (red) | See reserved list below |

**Accent (blue) reserved for (explicit — never "all interactive elements"):**
1. The **Save (primary) button fill** — `--color-accent`, hover `--color-accent-strong`. *(This closes the Phase-9-logged gap "Save-button accent → P12".)*
2. The **`:focus-visible` ring** on every focusable field/control (`2px solid var(--color-accent)`, `outline-offset: 1px`) — the existing input/select/Browse… focus treatment, extended to the picker cells/swatches and both buttons (a11y, UI-06 foundation — full app-wide sweep is Phase 13, but the form's own focus ring is in-scope here).
3. The **selected emoji-cell / color-swatch state** indicator (selected ring/border) — the picker's "this is chosen" affordance (D-03). Selected-swatch may keep the existing `--ink` ring OR move to `--color-accent`; tune in ui-lab (Discretion).

**Danger (red) reserved for (explicit — spend only where it matters):**
1. **Inline validation error text** under a field when the value is genuinely invalid (D-04).
2. The **surfaced main rejection** — "Working directory not found" (CR-01) rendered inline in the form on Save/Start, in the `--color-danger` ramp (precedent: Phase-10 D-15 danger ramp + the existing `.context-menu-item-danger` `color-mix(in oklch, var(--color-danger) 8%, transparent)` wash idiom).
3. **NOT** the Save button. *(The shipped `.modal-btn-confirm` is red because it was reused as a destructive-confirm button; in the form the primary action is constructive — Save must be `--color-accent` blue, not the inherited danger red. This is a required change, not discretion.)*

**Empty-name hint is NEUTRAL, not red:** the "keeps current name" affordance (Phase-4 discretion, D-04) is a calm `--ink-faint` helper, never the danger ramp — an empty name is a valid choice, not an error.

**60/30/10 read:** the white dialog card dominates (~60%); input borders + the grouped "Launch" container + hairline dividers are the secondary structure (~30%); the one blue Save fill + focus rings + the picker-selected ring (and, only on a real error, the red helper) are the ~10% spent on "the action" and "the one thing that needs fixing."

## Form Structure Contract (D-02 — the headline of UI-04)

The form is restructured from a raw stack of `.edit-field`s into **two semantic groups, single column**, each with a section subhead + a hairline divider. The grouping REUSES the Phase-4 live-vs-restart split (the pure `splitEdit` reducer in `session-edit.ts`) so the structure mirrors the data model the user already experiences.

| Group | Section subhead | Fields (in order) | Apply semantics | Notes |
|-------|-----------------|-------------------|-----------------|-------|
| **A — Identity** | `IDENTITY` (small-caps subhead) | 1. Name (`edit-name`) 2. Icon/color (`IconPicker`) | Applies **LIVE** (`onSaveLive`) — no respawn, logicalId preserved | The picker (D-03) lives here; name is the first focused field on open |
| **B — Launch** | `LAUNCH · APPLIES ON RESTART` (reuse the existing `applies-on-restart` hint copy/testid as this group's subhead) | 3. Working directory + Browse… (`edit-cwd` + `browse-cwd`) 4. Shell (`edit-shell` select) 5. Startup command (`edit-startup`) | Persists to main (`onSaveProfile`) — takes effect on next Start | This is today's `.edit-restart-group`; keep the grouped/recessed container, add the section subhead + hairline divider treatment |

**Divider treatment:** a hairline (`--line` / `--line-soft`) horizontal rule OR the recessed group surface (`--bg-sunk`) separates the two groups — exact treatment (rule vs surface vs both) tuned in ui-lab (Discretion). Single column only — no two-column layout (keeps the modal narrow, small-laptop-friendly, D-02).

**Picker polish (D-03 — Area B of CONTEXT):** the existing `IconPicker` (emoji grid + free-text emoji input + color-swatch row) is polished into a **designed grid/popover** — proper hover + selected states from the tokens, an aligned swatch row, a tidy preview. It stays the `emoji | color` model; **no new glyph system**. UI-04's "real icon/color picker" is satisfied by a real *picker UI*, not new glyphs. Inline grid (current) vs popover is a geometry Discretion (D-03) — tune in ui-lab; if it stays inline, ensure the dialog still fits `max-height: calc(100vh - 64px)` with overflow.

The validation strings are fixed literals — they never echo the raw rejected path beyond what main already returns sanitized.

## Interaction Contract

This phase is presentation + lightweight-validation; the data-flow behavior (live vs restart split, Browse…, hydration) is FROZEN and already implemented. The visual STATES of interaction are specified here. The full app-wide hover/focus/active sweep is Phase 13 (UI-06); the form's OWN focus/hover/validation states are in-scope.

| Interaction | Visual contract |
|-------------|-----------------|
| Open / focus | First field (`edit-name`) auto-focuses on open (existing). Dialog is `role="dialog"` `aria-modal="true"` `aria-labelledby={titleId}` (existing — keep). Backdrop click + Esc = cancel (existing ConfirmModal skeleton — keep). |
| Field focus | `:focus-visible` → `2px solid var(--color-accent)` ring, `outline-offset: 1px` (existing input/select/Browse… treatment — extend to picker cells/swatches + both buttons). Compositor-friendly (outline only). |
| Input hover/active | Border stays `--line`; background may warm to `--bg-sunk` on hover for the neutral buttons (existing Browse… + Cancel idiom). No layout-bound animation. |
| Picker — emoji cell | hover → `--bg-sunk` wash; selected → `--line`/`--color-accent` ring + `--bg-sunk` fill + `aria-pressed=true` (existing `.emoji-cell.selected`, polished). |
| Picker — color swatch | selected → ring (`--ink` or `--color-accent`) + `aria-pressed=true` (existing `.color-swatch.selected`, polished). Live preview reflects the choice immediately (existing `renderIcon` preview). |
| Browse… (SESS-06) | Opens the **native** open-directory dialog (main owns it via `pickDirectory` / `dialog:pick-directory`). On a chosen path → fills `edit-cwd` with the absolute path; on Cancel (null) → field unchanged. **No new bridge key** — `pickDirectory` already exists (key 19; `EXPECTED_API_KEYS` stays 20). CR-01 still gates the value at Start. |
| Inline validation (D-04) | Renderer-cheap, on-the-fly: empty name → neutral "keeps current name" hint; non-absolute cwd → neutral format hint; startup optional. **On Save/Start**, main's existing "Working directory not found" rejection is surfaced INLINE under the cwd field in the danger ramp. **NO `validatePath` existence-probe IPC** — directory existence is already guaranteed by main's CR-01 guard and Browse… only returns existing dirs (D-04). Validation tone: calm, low-contrast; red only on a genuine error. |
| Save / Cancel | Save = accent-blue pill (constructive). Cancel = quiet neutral. Pill shapes (`--radius-lg`). Save reads as THE action; Cancel recedes. |
| Prefill on open (SESS-05) | The modal seeds every field from the session record (existing `useEffect` L68–75). The record is refreshed from main via `rehydrateProfiles()` after spawn and after save, so a re-opened Edit shows the actually-persisted cwd + startupCommand (SC2). **Verify-and-finish, not greenfield** — confirm the live round-trip; close the O-1 first-open default-cwd display (resolved-home vs empty — pick the clearer behavior in ui-lab). |

**Motion:** only compositor-friendly properties (`opacity`, `transform`, `box-shadow`, `background`, `outline`) at `--duration-fast` (120ms) `--ease-standard`. No layout-bound property animation (web/performance.md). No new motion system (Phase 13).

**Keep-alive guard (Core Value):** the form is a **modal** — renderer-only, it never touches the xterm / PTY / fit path. Terminal fidelity is safe by construction, but the full suite (incl. the fidelity smokes) must stay GREEN. `EXPECTED_API_KEYS` stays **20** — no bridge change (D-04).

**Selector contract (frozen-or-update-in-lockstep — Rule-1 discipline):** the modal's `data-testid`s must SURVIVE the restructure, or be renamed WITH their tests in the same plan:
`session-edit-modal`, `edit-name`, `edit-cwd`, `browse-cwd`, `edit-shell`, `edit-startup`, `applies-on-restart`, `edit-save`, `edit-cancel`, plus the picker testids `icon-picker` / `edit-emoji-text`. Consumers: the `session-edit` smoke (`tests/smoke/`) and the ui-lab `edit-modal` surface (`tests/ui-lab/surfaces.ts` L400–417, and the `sidebar-populated` / `inactive-recipes` surfaces that drive the modal). Any rename ripples to all of them in the same plan. (The `Save changes` copy change touches the visible label ONLY — `edit-save` / `edit-cancel` testids are unchanged.)

## Verification Protocol (carried from CONTEXT — MANDATORY, Phases 10–13)

The ui-lab loop is the visual source of truth. No visual claim without a capture.

- **Baseline tag before first edit:** `UI_LAB_TAG=before-phase12 npm run ui:shots` (capture the current raw-stack form).
- **CSS-only value tweaks** may preview via `UI_LAB_LIVE_CSS=1`; **the structural TSX regroup (two semantic groups, polished picker) MUST use `npm run ui:shots:fresh`** — live-CSS injection previews old markup.
- **Surfaces (O-3):** the `edit-modal` surface already exists (`surfaces.ts` L400–417) with a `DESIGN-RUBRIC.md §edit-modal` section. This phase MUST **add a validation-error variant surface** (e.g. `edit-modal-validation`: open the modal, drive an invalid cwd, capture the inline danger-ramp error) so the D-04 inline-validation claim has a capture to score, AND **update the `edit-modal` rubric lines** to reflect the two-group structure + the picker polish + the blue Save (currently the rubric does not assert grouping or the accent-Save fix).
- **Phase gate:** full `npm run test` GREEN + a **packaged no-injection** capture scored against `tests/ui-lab/DESIGN-RUBRIC.md §edit-modal` (+ the new validation variant) + a **BLOCKING end-of-phase human-verify** for the visual SC1 (the canonical scan-test: "one cohesive designed surface") that covers SESS-05 O-1 (first-open default-cwd display) and SESS-06 O-2 (Browse… end-to-end on the packaged app). The Nyquist gate flips ONLY on an explicit unqualified operator "approved."
- **Guard tests stay GREEN in lockstep:** `tokens-completeness.test.ts` (every `var(--token)` resolves; no banned literals — new form CSS uses `var()` only), `security.guard.test.ts` (`EXPECTED_API_KEYS` === 20), the `session-edit` smoke, and the fidelity smokes.
