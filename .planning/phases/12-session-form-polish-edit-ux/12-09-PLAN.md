GAP-12-C (residual swallow): the literal "edit a bad cwd → live restart → pid -1 + notice" path is NOT reachable
(updateProfile rejects the bad cwd at persist, so restart succeeds with the prior cwd). The genuine residual bug
is the DELETED-after-save / corrupt-store edge: create() returns pid<=0 + a 'Working directory not found' notice,
but the renderer SWALLOWS it — `handleRestart` (SessionManager ~209) has no pid<=0 branch, and `applyStatusEvent`
(ITEM-4) treats a notice-bearing event as informational and keeps status 'running' → a stale-'running' row on a
dead PTY with an unsurfaced errorMessage. FIX (per the typescript-reviewer): put the fix in handleRestart's `else`
branch — on pid<=0 clear the optimistic running flip / dead ptyPid so the already-fired error state wins and the
IdleCard + notice surface. Do NOT change applyStatusEvent's contract (a notice must stay informational; that is
tested).

GAP-12-E (no silent cwd drop): typing a non-existent ABSOLUTE cwd, Save closes with NO feedback — updateProfile's
isValidCwd silently keeps the prior value, and `validateSessionForm` only hints on FORMAT (non-absolute), so a
format-valid-but-nonexistent path gets nothing. FIX: detect the drop renderer-side by comparing the submitted cwd
against the persisted (post-save) cwd — `rehydrateProfiles` already re-reads `listSessions` (main's truth) after
save, so the authoritative persisted cwd is available with NO new bridge key. When they differ, surface an inline
'that folder doesn't exist — kept the previous directory' notice and KEEP the modal open instead of closing it
silently. Main stays the validator of record (the renderer adds no existence probe).

Purpose: a dropped working directory is never silent, and a failed restart-to-apply lands its error where the
user acted — closing the operator's #6 re-gate failure and the GAP-12-E expectation mismatch.
Output: a pure cwd-drop reducer + the two renderer wirings + the relocated renderer-side surface regression test.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer edit form → main updateProfile | The submitted cwd (untrusted user input) crosses into main; main's CR-01 isValidCwd is the validator of record |
| main listSessions (authoritative persisted cwd) → renderer | The post-save truth the renderer reads back to detect a dropped cwd (existing read, no new key) |
| main create() pid<=0 + onPtyStatus notice → rendered error | A failed restart's rejection reaches the renderer over the existing status channel; must surface, not be swallowed |

This is a renderer-only, USER-INITIATED, single-shot change. (1) NO RETRY STORM: the cwd-drop check runs ONCE per
Save off the SAME listSessions re-read rehydrateProfiles already performs — no new IPC, no polling, no loop.
(2) NO RESOURCE RUNAWAY: keeping the modal open on a drop is a single state flag; no timer, no subscription added.
(3) NO COST/TOKEN/LLM. (4) NO UI STALL: the compare is synchronous after the existing async re-read; the modal
stays responsive. (5) NO CONCURRENCY AMPLIFICATION: the modal is singular; the restart-to-apply prompt is modal
and one-at-a-time. (6) Terminal fidelity is untouched — this plan modifies only the form/modal + the renderer row
state; it never touches the xterm/PTY/fit path. EXPECTED_API_KEYS stays 20 (no new bridge key).
