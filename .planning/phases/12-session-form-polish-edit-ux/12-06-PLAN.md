<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer restart request → main create() | The restart-to-apply prompt calls ptyRestart(id); main re-spawns from the PERSISTED record.cwd/shell — an untrusted cwd would cross here |
| main create() cwd → pty.spawn | A bad/missing working directory must not reach pty.spawn |
| onPtyStatus notice → rendered error | The CR-01 rejection string reaches the renderer over the existing status channel |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-06-01 | Tampering | a bad cwd reaching pty.spawn on restart | mitigate | UNCHANGED CR-01 isValidCwd in main: updateProfile rejects a non-existent/relative cwd at persist (keeps prior value); create() pre-validates the resolved cwd and returns pid -1 + an 'error' notice WITHOUT spawning (pty-manager L305-313). The renderer never validates — main stays the validator of record |
| T-12-06-02 | Denial of service | concurrent / rapid restart (DEBT-02 CR-02) | mitigate | restart() has the respawned-once guard (pty-manager L815-821) and the create({id}) stale-exit guard (L514-526); the prompt fires a SINGLE ptyRestart per confirm, and handleRestart's pid>0 guard avoids a stale optimistic flip. No retry loop introduced |
| T-12-06-03 | Information disclosure | the rejection notice text | accept | main's notice is sanitizeNotice-stripped (C0/C1) and rendered as a React text node; no new interpolation added |
| T-12-06-04 | Spoofing | ptyRestart on a forged id | accept | restart() id-validates against the sessions store (unknown id → reject, T-03-01); the prompt only ever passes the edited session's real id |

## Reliability & Cost (§6.5) — explicitly stated (light)
This is a USER-INITIATED, SINGLE restart per confirm — there is NO retry storm (one ptyRestart per "Restart now"
click), NO cron / scheduled trigger, NO LLM/token cost, NO concurrency amplification (the prompt is modal — one
at a time; restart()'s respawned-once + stale-exit guards prevent a double-spawn even under a rapid click). The
restart preserves the kept SessionView's xterm (scrollback kept). The PTY/xterm/fit data path is NOT modified —
restart reuses the existing create()/SessionView attach machinery, so Core Value (terminal fidelity) is
unaffected by construction.
</threat_model>
