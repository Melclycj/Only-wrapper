<objective>
Close GAP-12-D (part 1, the root cause): NO application `Menu` is configured anywhere in `src/main`, so the
standard macOS Edit shortcuts (Cmd+A select-all, Cmd+C/V/X, Cmd+Z) have no role and do not function in the form
inputs — and Cmd+A bubbles out and closes the modal (the renderer overlay/Cmd-A half is handled in 12-05's
sibling renderer plan 12-04).

Root cause (code-confirmed): `grep -rn "Menu|setApplicationMenu|buildFromTemplate" src/main` returns ZERO matches
(only a comment in index.ts L121). Electron's default menu provides these roles, but it is replaced by `null` on
some launch paths and is unreliable for a Forge/Vite app — the fix is to explicitly build and set an application
Menu with the standard editing roles.

Purpose: standard, OS-native text editing (select-all, copy, paste, cut, undo/redo) in every form input, while
the existing app-wins keyboard chords (Cmd/Ctrl+1-9 switch, Cmd+K clear, Cmd+F find — intercepted in
`before-input-event`) keep working.
Output: a pure `app-menu.ts` template builder + a unit test + the `Menu.setApplicationMenu(...)` wiring at
whenReady, mirroring the `lifecycle.ts` electron-free-helper pattern.
</objective>
