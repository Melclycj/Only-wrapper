WRONG, synthetic, slow-but-matching failure mode. THIS round does NOT touch the budget numbers.

THE FIX = MARKER RE-SEND. While `!settled`, RE-SEND the SAME-nonce `: <nonce>\r` marker on a short interval
(the marker is a stateless POSIX `:` no-op — D-01 — so re-sending is idempotent and changes no shell state).
Once the shell reaches a ready prompt, a re-sent marker echoes as `<prompt>… <nonce>` on a `\n`-preceded
produced line → the EXISTING `\n[^\n]*<nonce>` matcher matches cleanly (the typed-ahead redraw is no longer
relied upon). KEEP the existing idle-extend. The re-send loop is BOUNDED by the EXISTING hard ceiling
(READINESS_HARD_TIMEOUT_MS): a chatty-but-never-ready shell still hits the hard ceiling and takes the UNCHANGED

## Reliability & Cost (§6.5 — MANDATORY for a retry mechanism)
This plan ADDS a retry (the marker re-send), so the R&C lens is load-bearing:
1. **RETRY-STORM BOUND** — the re-send fires at most once per READINESS_RESEND_INTERVAL_MS (~1200–1500ms), and ONLY
   while `!settled`. The first match stops it (clearTimers disposes the resend slot). It is not request-amplifying:
   one marker write per interval, into one PTY, for one session.
2. **RE-SEND INTERVAL CAP** — the interval is a fixed exported constant; there is no exponential growth and no
   per-byte re-send. The marker is a tiny no-op write.
3. **TOTAL-ATTEMPT CAP UNDER THE HARD CEILING** — the re-send is BOUNDED by READINESS_HARD_TIMEOUT_MS (15000ms),
   which is NEVER reset by a re-send (only the idle timer extends on produced bytes). So the maximum number of
   re-sends is ⌈HARD/INTERVAL⌉ ≈ 10–12, then the hard ceiling fires the UNCHANGED D-04 give-up. No unbounded loop.
4. **NEVER-READY SHELL FALLS BACK CLEANLY** — a chatty-but-never-ready shell (or one that swallows every marker)
   hits the hard ceiling and takes the D-04 fallback: flush the bare prompt once, emit READINESS_FAIL_NOTICE,
   NEVER inject. Proven by the never-ready control in the Task-3 regression.
5. **NO RESOURCE RUNAWAY** — one interval timer per spawn, cleared on match/give-up and guarded against a
   replaced/dead child; no accumulation across restarts (each create() owns its own timers).
6. **CORE-VALUE / FIDELITY** — the data path outside the probe gate is untouched; the marker is a no-op; D-02/D-04
   hold; the working dormant-Start auto-run and `claude --rc`/vim/ssh/REPL fidelity are unregressed.
</threat_model>
