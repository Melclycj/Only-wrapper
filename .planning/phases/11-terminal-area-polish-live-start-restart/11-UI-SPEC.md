# Phase 11 — UI Design Contract

> Visual and interaction contract for the **terminal-area polish + session-lifecycle simplification** (UI-03 + SESS-07). Generated by gsd-ui-researcher, verified by gsd-ui-checker (6/6 dimensions PASS, 2026-06-13).
>
> **Source note:** This phase composes the LOCKED Phase-9 token system (`src/renderer/tokens.css`) onto the **second** real surface — the terminal area — exactly mirroring the Phase-10 sidebar method (`10-UI-SPEC.md`). No design system is re-decided here. Nearly every value below is pre-populated from `tokens.css`, `11-CONTEXT.md` (D-01…D-05), the Phase-10 precedent, and the live source (`SessionManager.tsx`, `IdentityHeader.tsx`, `IdleCard.tsx`, `ConfirmModal.tsx`, `terminal.css`) — not from new questions. The visual direction is "Switchboard — warm cozy parlour" (DESIGN.md), locked.
>
> **Two threads:** (1) **UI-03** — turn the active IdentityHeader + terminal viewport into ONE framed, breathing **unified session card** floating on cream `--bg`, with the dormant IdleCard + WelcomeEmptyState reading as its siblings; (2) **SESS-07** — the live control cluster becomes **Clear + Remove ONLY** (no Restart anywhere), Remove styled in the danger ramp, and the Remove/Delete confirm copy escalates when an agent is busy (D-04). Recycle = Remove → Start (dormant Start ▶ already exists).

## Spacing Scale

This phase consumes the SAME `--space-*` scale Phase 10 first applied (defined Phase 9, 09-CONTEXT D-01). All NEW terminal-area geometry — card gutter from the cream `--bg`, card inner padding, header cap padding, control-cluster gaps — MUST be expressed with these tokens. The existing header/idle-card geometry currently in `terminal.css` (the `8px 14px` header pad, the idle-card padding) snaps to the nearest token step during the restyle (Discretion, tuned via ui-lab).

**Declared spacing scale — formal contract (4px base; multiples of 4 only):**

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| `--space-1` | 4px | Control-cluster gaps (Clear ↔ Remove), icon-to-text micro gaps (carries the existing 4px `.header-controls` gap) |
| `--space-2` | 8px | Header cap vertical padding, identity gap (icon ↔ name), badge inner gaps |
| `--space-3` | 12px | Header cap horizontal padding (snap of the current `14px`); card-edge ↔ content insets |
| `--space-4` | 16px | **Card gutter** — the breathing room between the unified card and the cream `--bg` edges (the headline "not edge-to-edge" move); IdleCard internal block spacing |
| `--space-5` | 20px | Generous card inner padding option for the IdleCard body / config block |
| `--space-6` | 24px | Major card breathing room (top/bottom gutter on the empty + idle states if the card reads cramped at 16px) |
| `--space-8` | 32px | Reserved — large empty-state centering rhythm (WelcomeEmptyState framing only) |

**Card-gutter contract (the D-03 headline geometry — Discretion range, tuned in ui-lab):** the unified card is inset from the `.terminal-area` edges by a gutter in the **`--space-4` (16px) → `--space-6` (24px)** band. The contract default is **`--space-4` (16px)** on all four sides; the ui-lab DESIGN-RUBRIC pass may step it to `--space-5`/`--space-6` if 16px reads tight against the cream ground. The same gutter value applies to the live card, the IdleCard sibling, and the WelcomeEmptyState framing so the three states read as one family.

**8-point compliance:** Every value in the formal scale above is a multiple of 4. The canonical 4/8/16/24/32 steps are all present (`--space-1`/`--space-2`/`--space-4`/`--space-6`/`--space-8`), with 12px and 20px as on-scale intermediate steps.

> **Footnote — value-preserving migration aliases (NOT part of the formal spacing contract):** the `--space-0_5` (2px) / `--space-1_5` (6px) / `--space-2_5` (10px) half-steps carried from Phase 9/10 exist ONLY to migrate pre-existing pixel values without changing rendered geometry. No NEW terminal-area geometry is authored against them; new card/gutter decisions use the formal scale above.

**Exceptions:**
- The xterm content area is sized by `@xterm/addon-fit` against its inner box, NOT by a spacing-scale step. Its dimensions are computed, not authored (see Interaction Contract — fidelity guardrail).
- The status-dot / pill shapes stay literal `999px` (full-round, not a scale step — per `tokens.css` note).
- The header control footprint (`24×24` `.row-control`, `8px 16px` `.header-control-clear`) is a sized element family carried verbatim from the shipped header / `.modal-btn` footprint; element dimensions, not spacing gaps.

## Typography

Terminal-area chrome is composed from `--font-ui` (Nunito) only; terminal content + the IdleCard read-only literals use `--font-mono` (JetBrains Mono). Two weights total: 400 (regular) and 700 (bold) — matching the loaded Nunito faces; no third weight is introduced. The scale below is the SET this surface uses, value-preserving from the shipped header/idle-card blocks, retuned only where the unified-card cap needs it.

| Role | Size | Weight | Line Height | Where |
|------|------|--------|-------------|-------|
| Header session name | 14px | 700 | 1.2 | `.identity-header .row-name` — the active session identity in the card cap (currently `font-weight:600`; **moves to 700** to match the Sidebar `.row-name` identity contract from 10-UI-SPEC — single identity weight everywhere) |
| Header status badge | 12px | 700 | 1 | `.status-badge` label + dot — the live status word (Running / Waiting for you / …); inherits the shipped badge type |
| Clear control label | 13px | 700 | 1 | `.header-control-clear` — the one text-labelled control (carried verbatim from the shipped 13px/700) |
| IdleCard session name | 16px | 700 | 1.2 | `.idle-card-name` — the dormant card's identity (slightly larger than the header name; it is the focal element of an otherwise-quiet card) |
| IdleCard label | 12px | 700 | 1.3 | `.idle-card-label` — "Working directory" / "Shell" / "Startup command" small labels, `--ink-faint` |
| IdleCard value (mono) | 13px | 400 | 1.4 | `.idle-card-value` — read-only cwd / shell / startup literals in **`--font-mono`** (JetBrains Mono) so they read as terminal literals (TERM-05 boundary cue) |
| Confirm modal title | (shipped `.modal-title`) | 700 | 1.2 | `ConfirmModal` heading — unchanged shipped type; copy branch changes only the *words* (D-04), not the type |
| Confirm modal body | (shipped `.modal-body`) | 400 | 1.4 | `ConfirmModal` body — unchanged shipped type; the D-04 escalation changes the *string* only |

**Line-height policy:** chrome body/label text runs compact (1.2–1.4 — calm parlour chrome, DESIGN.md north star, NOT the generic 1.5 web default; terminal-adjacent UI runs tight). Single-line glyph/badge rows use 1 to avoid emoji/baseline jitter (existing Pitfall-6 guard). The xterm terminal content line-height is owned by the xterm theme/font config — OUT OF SCOPE (Core-Value data path untouched).

**Discretion (CONTEXT):** the header name may land at 14 or 15px through the ui-lab loop (both already exist in the codebase); the contract value is **14px/700** unless the DESIGN-RUBRIC pass shows it reads weak against the new framed cap, in which case 15px/700 is the only permitted alternative.

## Color

The terminal area uses the LOCKED Switchboard token set. The north star (carried from 10-CONTEXT): **calm low-contrast chrome; spend color only where it matters.** The terminal content is the focal area; the surrounding card frame, header cap, and controls recede. All values are `var()` references — no literals (guarded by `tokens-completeness.test.ts`).

| Role | Value (token) | Usage |
|------|---------------|-------|
| Dominant (60%) | `--bg` = `oklch(0.975 0.008 85)` (warm white) | The `.terminal-area` ground the unified card floats on (the visible gutter); the WelcomeEmptyState ground |
| Secondary (30%) | `--surface` = `#ffffff` + `--line` / `--line-soft` borders | The unified card frame: header cap (`--surface`), card border (`--line`), the IdleCard surface; the soft hairline that joins/separates header cap and terminal |
| Terminal field | `--term-bg` = `#1e232c` (charcoal-indigo) + `--term-text` / `--term-faint` | The xterm viewport interior INSIDE the card (`.viewport-stack`); NOT pure black (RUBRIC line). This is the focal surface |
| Accent (10%) | per-session `--accent` (resolved by `presentation(status, agentState)`) | See reserved list below |
| Destructive | `--color-danger` = `oklch(0.58 0.16 25)` (red) + `--color-danger-strong` hover | The **Remove** control in the live cluster (D-15 precedent); the Delete/Remove confirm button (shipped `.modal-btn-confirm`); the escalated agent-busy confirm copy is text, not a new color |

**Accent reserved for (explicit — never "all interactive elements"):**
1. The **live status badge** in the header cap — dot + word colored by the session's *status* accent via `presentation(status, agentState)` (running=blue, finished=green, idle=slate, error=red). Not a fixed brand blue.
2. The **waiting amber** — when `agentState === 'waiting'` the header badge resolves to `--accent-waiting` (amber `oklch(0.66 0.15 60)`), reserved EXCLUSIVELY for waiting, exactly as in the sidebar (locked Phase-6 contract). No new amber treatment is introduced on the terminal card frame — the badge is the single waiting signal on this surface (the sidebar carries the row wash).
3. The **IdleCard `▶ Start` button** uses the brand-blue accent language (`.idle-start-button`, the one fixed-blue "go" affordance — mirrors the dormant Start ▶ on the Inactive-List entry). The error-branch **Retry** button shares this blue; **Edit** stays neutral.
4. The **focus ring** — `2px solid var(--color-accent)` `:focus-visible` outline on every control (Clear, Remove, Start, Retry, Edit, confirm buttons) — carried verbatim from the shipped controls (a11y, locked).

**Status accent ramp (from `status-colors.ts` → `tokens.css`, do NOT re-decide):**

| State | Token | Color | Label |
|-------|-------|-------|-------|
| running / in-progress | `--accent-running` (= `--color-accent`) | blue `oklch(0.62 0.14 248)` | "Running" / "In progress" |
| waiting | `--accent-waiting` | amber `oklch(0.66 0.15 60)` | "Waiting for you" |
| exited (clean) | `--accent-finished` | green `oklch(0.6 0.13 150)` | "Finished" |
| stopped / not_started | `--accent-idle` | slate `oklch(0.64 0.02 260)` | "Stopped" / "Idle" |
| error | `--accent-error` (= `--color-danger`) | red `oklch(0.58 0.16 25)` | "Error" |

**Danger ramp for Remove (D-15 precedent — the SESS-07 destructive affordance):** the live cluster's **Remove** control reads in the danger ramp. The contract default mirrors the Phase-10 sidebar close treatment: **neutral `--ink-soft` at rest, warming to `--color-danger` on `:hover` / `:focus-visible`** with an optional `color-mix(in oklch, var(--color-danger) ~8%, transparent)` wash (precedent: `terminal.css` danger hovers). It must read as the destructive affordance of the cluster WITHOUT shouting red at rest (calm-chrome north star). Exact rest-vs-hover danger intensity tuned through ui-lab against the RUBRIC.

**60/30/10 read:** the cream `--bg` gutter the card floats on dominates the surround (~60%); the white `--surface` card frame + header cap + hairlines are the secondary surface (~30%); the status badge accent, the one blue Start, and the Remove danger-on-hover are the ~10% spent only on "what state is this session" and "the destructive action." The `--term-bg` charcoal terminal is the focal *content* field inside, distinct from the chrome 60/30/10.

| Element | Copy |
|---------|------|
| Primary CTA — live cluster | **`Clear`** — text-labelled button, `aria-label="Clear terminal"`, `title="Clear terminal"`. Wipes the visible buffer (client-side `term.clear()`, no PTY write — D-12) |
| Destructive CTA — live cluster | **`✕` Remove** — icon-only glyph button, `aria-label="Remove session"`, `title="Remove session"`, danger ramp. The live header's destructive action (D-03/D-06) |
| Dormant CTA — IdleCard | **`▶ Start session`** — `data-testid="idle-start-session"` (existing); the discoverable recycle endpoint for a Removed session (SESS-07) |

### Confirm-modal copy contract (the D-04 agent-aware escalation — this phase's authored copy)

The `ConfirmModal` stays a dumb controlled component; the branch logic lives in `SessionManager` (~698-716). Today the body has three non-agent branches (delete / configured-running / ephemeral). This phase adds an **agent-aware escalation overlay**: when the target row's `agentState ∈ {working, waiting}`, the body string escalates to name the in-progress work. Title and confirm-label words are unchanged; only the **body** escalates.

| Condition (target row) | Title | Body | Confirm label |
|------------------------|-------|------|---------------|
| Delete (dormant/ephemeral), agent idle | `Delete "{name}" permanently?` | `This permanently deletes the saved session — its recipe is gone for good.` *(shipped — unchanged)* | `Delete` |
| Remove (configured live), agent idle | `Remove "{name}"?` | `This ends its running process and moves the session to the Inactive List. You can start it again later.` *(shipped — unchanged)* | `Remove` |
| Remove (ephemeral live), agent idle | `Remove "{name}"?` | `This ends its running process and removes the session.` *(shipped — unchanged)* | `Remove` |
| Remove/Delete, **agentState = working** | (same as the idle title for that mode) | **`Claude is still working in this session — closing it now will end the task mid-run. {idle-body}`** | (same as idle) |
| Remove/Delete, **agentState = waiting** | (same as the idle title for that mode) | **`This session is waiting for your input — closing it now will discard what it's asking for. {idle-body}`** | (same as idle) |

**Escalation rules (contract):**
- The escalation is a **prefix sentence** prepended to the existing idle body (so the consequence — Inactive List vs permanent delete — is never lost). `{idle-body}` is the shipped string for the resolved mode/configured branch.
- Escalation fires ONLY for `agentState ∈ {working, waiting}`. `running`-without-agent-overlay, `exited`, `stopped`, `error`, `not_started` use the shipped idle body verbatim.
- The wording must name the **specific** risk (mid-run task vs discarded input), not a generic "are you sure" — the operator's intent (D-04) is that a busy session feels consequential to close.
- `agentState` is the renderer-only overlay already on the active record (`activeRecord.agentState`, threaded to IdentityHeader today); `SessionManager` reads it for the close target. **No new IPC, no persisted field** (D-06 — agent state is never persisted).
- Final exact wording is tunable through the ui-lab agent-busy-confirm capture (Discretion); the two strings above are the contract default. "Claude" may be generalized to "The agent" if the planner prefers product-neutral copy — either is acceptable; the *consequence-naming* is the locked requirement.

**Empty / loading / error STATE DESIGN is NOT this phase** (Phase 13 / UI-05). The WelcomeEmptyState + IdleCard body strings are existing; only their **framing** must read as a sibling of the new card. No new empty/error copy is authored here beyond the D-04 escalation.

**Copy discipline:** all user-controlled strings (`name`, cwd, startupCommand) render as React text nodes (auto-escaped). No `dangerouslySetInnerHTML`, no HTML interpolation. The confirm `{name}` interpolation stays inside the existing template literal (shipped).

### Fidelity guardrail (D-03a — BLOCKING, Core Value)

This is a hard interaction constraint, not a refinement. The card framing is a **container-layer** treatment ONLY:

1. **Radius / padding / shadow apply to the card WRAPPER, never to the xterm element.** The xterm viewport (`.session-view .xterm`/`-viewport`/`-screen`, currently `inset:0` filling `.term-mount`) is never given a border-radius, never clipped, never padded. A rounded corner over a terminal masks the **container**, not terminal cells — no glyph is ever cropped by a corner.
2. **`@xterm/addon-fit` MUST re-fit to the new inner box.** When the card padding/gutter changes the `.viewport-stack` inner dimensions, fit recomputes cols/rows against the new box — no stale cols/rows, no clipped last row (Open question O-2 — the planner must confirm the re-fit path fires on the layout change, e.g. via the existing ResizeObserver/fit trigger, not a one-shot mount fit).
3. **No regression in:** scroll, alt-screen enter/exit, resize, ANSI, truecolor, the keep-alive hidden-pane behavior (`visibility:hidden`, never `display:none`). The `app-restart-restore`, scroll, and alt-screen smoke specs stay GREEN.
4. **Renderer-only.** `EXPECTED_API_KEYS` stays **20** — no IPC bridge key added or removed (the hidden `ptyRestart` machinery is KEPT per D-01, just un-surfaced). `src/main/*` is untouched.
