# Plan 11-04 — GAP-11-A: faithfully match the mockup (inset terminal well + breathing + warmer cream + breadcrumb header + status pills)

<objective>
Close GAP-11-A. The Phase-11 terminal card (11-02) was operator-rejected at the gate (2026-06-14):
"没看出来呼吸感 … 很丑,甚至不如那个 html draft". Redesign the terminal area to **faithfully match the
mockup IDE view** — rendered at `.planning/design/rendered/switchboard-ide-view.png` — WITHOUT
regressing the already-APPROVED functional gates (SC1-CV terminal fidelity / SC2 Working-vs-Inactive /
SC3 no-restart + Remove→Start recycle / SC4 identity / D-04 agent-busy copy). This is a VISUAL +
small-feature gap-closure round; the lifecycle/IPC behavior is frozen.
</objective>

<design_target>
**STUDY `.planning/design/rendered/switchboard-ide-view.png` before writing any CSS.** (Re-render
the live mockup any time with `node_modules/.bin/electron /tmp/shoot-mockup.js` if it helps.)

The 5 properties the current build LACKS (operator opted into all 5, "忠实对齐 mockup"):

1. **Inset rounded terminal WELL** — the charcoal `--term-bg` terminal is a rounded block sitting
   INSIDE a white `--surface` card with generous padding around it (the white card surface shows
   *around* the terminal). The current build makes the terminal flush edge-to-edge — THAT is the
   headline miss. Add breathing room INSIDE the card, not just outside.
2. **Generous outer breathing room** — the card floats on the cream field with real margin (step
   the gutter up from the current `--space-4`).
3. **Warmer cream background** — tune `--bg` warmer toward the mockup's `#f3e6d6` (a warm cream),
   keeping it a `var()` token. Verify the whole token system still coheres (sidebar/cards/modals).
4. **Breadcrumb session header** — the header reads as a session tab + a path line
   (`local · {name} · {cwdTail}`) + the status on the right — like the mockup — not a flat strip.
5. **Status summary pills (top strip)** — a slim strip aggregating live counts by status, e.g.
   `2 Waiting · 5 Running · 2 Done · 1 Idle`, colored from the existing status ramp. This is a
   small NEW feature (count aggregation + a top bar); place it to match the mockup (top, near the
   app chrome). Reuse `status-colors.ts` / `presentation()` — do not re-derive colors.
</design_target>

<fidelity_guardrail priority="BLOCKING">
Core Value — SC1-CV (terminal fidelity) MUST stay PASS:
- The inset well's `border-radius` / `padding` / `overflow` go on a **WELL WRAPPER** element only,
  NEVER on `.viewport-stack` / `.session-view` / `.term-mount` / `.xterm*`. The xterm stays flush
  inside the well; the `ResizeObserver` (bound to `.term-mount`) re-fits to the well's smaller
  inner box automatically — DO NOT add a manual `fit.fit()`.
- No glyph may be clipped by the well's rounded corners: the charcoal `--term-bg` fills the rounded
  well and the xterm content insets enough that text never reaches the exact corner.
- The fidelity smokes `app-restart-restore` / `alt-screen-reset` / `pty-resize` MUST stay GREEN. If
  any goes red, STOP — do not loosen the test.
- `EXPECTED_API_KEYS` stays **20**; `src/main/*` byte-untouched. Renderer-only. Tokens-first (no
  literals; `tokens-completeness.test.ts` + `status-colors.test.ts` GREEN).
- The `terminal-well` wrapper is a small structural add in `SessionManager.tsx` (wrap the
  `.viewport-stack`); the `IdleCard` + `WelcomeEmptyState` must read as siblings inside the same
  framed card.
</fidelity_guardrail>
