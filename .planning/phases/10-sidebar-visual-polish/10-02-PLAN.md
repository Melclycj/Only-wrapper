<objective>
Restyle the session sidebar to an intentional two-line visual hierarchy in both expanded and
collapsed modes (UI-02 / SC1-SC4), closing the three Phase-9 sidebar gaps: name-crush (Gap 1),
unanchored inactive rows (Gap 5), and weak active distinction. Implements the locked D-01..D-13
decisions: two-line rows with a large icon tile, hover/keyboard-reveal controls, a filled +
left-edge-barred active card colored by status, an amber waiting treatment that fires on
non-active rows too, dashed eggshell recipe cards with an always-visible ghost ▶, and
small-caps section labels with counts.

Purpose: This is the first real surface to compose the Phase-9 token foundation — the first
consumer of the `--space-*` scale. The active row and the amber "Waiting for you" signal are
the product's soul ("which agent needs me"); everything else is calm low-contrast chrome so the
terminal stays the focus.

Output: restructured `Sidebar.tsx` (row JSX, two buckets, section counts), the full Phase-10
visual rule set in `sidebar.css` (consuming tokens), two new ui-lab evidence surfaces + their
rubric sections.

OPEN-Q1 RESOLUTION (RESEARCH A2 — resolved against source, do NOT re-investigate): a non-active
RUNNING session DOES carry `agentState`. SessionView's agent-state detector (`agentTick`
setInterval) is keyed on `id` only — NOT on `active` — and reads `term.buffer.active` viewport
lines, which needs no WebGL context, so it classifies HIDDEN/backgrounded panes
(SessionView.tsx ~L354-388, ~L329 unconditional term.write). SessionManager.handleAgentState
(~L564-572) stores `agentState` on ANY row whose `row.status === 'running'`, not just the active
one (its comment: "Computed for ALL running sessions (D-10), so a backgrounded session's amber
dot shows in the rail while you work elsewhere"). Therefore the D-09 `[data-agent="waiting"]`
amber wash WILL fire on non-active rows with zero new wiring — the row already receives
`agentState`, and `presentation(status, agent)` already resolves amber while running. Do NOT add
a parallel status path; just read the existing `agentState` and emit `data-agent` on the row.
</objective>
