## Spacing Scale

This phase is the FIRST CONSUMER of the `--space-*` scale that Phase 9 defined-but-did-not-apply (09-CONTEXT D-01). All sidebar geometry (row padding, gaps, section spacing, icon-tile margins) MUST be expressed with these tokens. Odd-ball one-off values currently in `terminal.css` (5px / 14px / 22px) snap to the nearest step (CONTEXT Discretion).

**Declared spacing scale — formal contract (4px base; multiples of 4 only):**

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| `--space-1` | 4px | Icon-to-text micro gaps, edge-bar-to-content |
| `--space-2` | 8px | Section divider padding, control gaps, secondary-line top gap |
| `--space-3` | 12px | Row horizontal padding, icon-tile ↔ text gap |
| `--space-4` | 16px | Default block spacing, section label padding |
| `--space-5` | 20px | Generous row block (two-line rows ~40% taller — D-01) |
| `--space-6` | 24px | Section breaks |
| `--space-8` | 32px | Major vertical rhythm |
| `--space-12` | 48px | Reserved (not expected in the sidebar) |

**8-point compliance:** Every value in the formal scale above is a multiple of 4. The canonical 4/8/16/24/32/48 steps are all present (`--space-1`/`--space-2`/`--space-4`/`--space-6`/`--space-8`/`--space-12`), with 12px and 20px as on-scale intermediate steps.

> **Footnote — value-preserving migration aliases (NOT part of the formal spacing contract):**
> The following three tokens carry sub-4px / non-multiple-of-4 values that exist ONLY to migrate the pre-existing `terminal.css` geometry into the token system **without changing rendered pixels** during this restyle. They are migration aliases, not design-contract spacing steps, and the planner/executor should treat them as such — no NEW geometry should be authored against them; new spacing decisions use the formal scale above. Where the ui-lab loop allows snapping a value to the nearest formal step without harming the layout, prefer that.
> - `--space-0_5` = 2px — hairline insets, dot ring offset (carried)
> - `--space-1_5` = 6px — tight inline gaps (dot ↔ word) (carried)
> - `--space-2_5` = 10px — row vertical padding, compact variant (carried)

**Exceptions:**
- The collapsed rail width (~52px icon-only) is a layout dimension, not a spacing-scale step (carried from Phase 4 `.collapsed`). Keep as-is.
- The icon tile is ~34px (D-04, "32–36px" rounded tile) — a sized element, not a spacing gap. Snapped to a single literal `34px` in CSS (between `--space-8` 32 and a 36 that isn't on-scale); acceptable as an element dimension.
- 999px pill radius (status dots, ghost ▶) stays literal — a full-round shape, not a scale step (per `tokens.css` note).

## Typography

Sidebar typography is composed from `--font-ui` (Nunito) only. The scale below is the SET this surface uses — value-preserving from the existing sidebar block in `terminal.css`, retuned only where the two-line restructure (D-01) needs it. Two weights total: 400 (regular) and 700 (bold) — matching the loaded Nunito faces; no third weight is introduced.

| Role | Size | Weight | Line Height | Where |
|------|------|--------|-------------|-------|
| Row name (line 1) | 14px | 700 | 1.2 | `.row-name` — primary session identity, full width, ellipsis on overflow (D-01) |
| Secondary line (line 2) | 12px | 400 | 1.3 | `.row-secondary` — status word + cwd tail / startup command, color `--ink-soft` (D-03/D-08) |
| Section label | 10px | 700 | 1 | `.sidebar-section-label` — small-caps, letter-spaced, `--ink-faint`, with `· {count}` (D-12) |
| Color-badge initial | 14px | 700 | 1 | inside the enlarged icon tile when icon kind = color badge (D-04) |

**Line-height policy:** body/secondary text uses 1.2–1.3 (compact, calm chrome — DESIGN.md north star, not the generic 1.5 web default; terminal-adjacent UI runs tight). Single-line glyph rows (icons, dots, section labels) use 1 to avoid emoji/baseline jitter (existing Pitfall-6 guard).

**Discretion (CONTEXT):** Exact name size may land at 14 or 15px through the ui-lab loop; both are already in the existing sidebar (`.row-name` 14px, header 15px). The contract value is **14px/700** unless the ui-lab DESIGN-RUBRIC pass shows the name reads weak — then 15px is the only permitted alternative (still weight 700).

## Color

The sidebar palette is the LOCKED Switchboard token set (warm low-contrast chrome). Calm by default; color is spent only on the active row and the waiting signal. All values are `var()` references — no literals (guarded by `tokens-completeness.test.ts`).

| Role | Value (token) | Usage |
|------|---------------|-------|
| Dominant (60%) | `--bg` = `oklch(0.975 0.008 85)` (warm white) / `--bg-sunk` for the rail | Sidebar rail background; inactive rows sit flat/transparent on it |
| Secondary (30%) | `--surface` = `#ffffff` + `--line` borders | The ACTIVE row's filled card; recipe-card surfaces |
| Accent (10%) | per-row inline `--accent` (resolved by `presentation(status, agent)`) | See reserved list below |
| Destructive | `--color-danger` = `oklch(0.58 0.16 25)` (red) | Remove/Delete menu items (D-15); close ✕ hover |

**Accent reserved for (explicit — never "all interactive elements"):**
1. The **active row's left edge bar** (3–4px) and card lift — colored by the session's *status* accent, not fixed brand blue (D-05/D-06).
2. The **waiting amber treatment** — amber left edge bar + light tint wash on any waiting row, active or not (D-09). Amber (`--accent-waiting`) is reserved EXCLUSIVELY for `waiting` and appears in exactly one presentation path (locked Phase-6 contract).
3. The **status dot** on the secondary line / collapsed rail — carries the status color; the word stays `--ink-soft` (D-08).
4. The **ghost ▶ Start button** fill-on-hover uses `--color-accent` (brand blue) — the one fixed-blue accent, on inactive recipe cards (D-13).

**Status accent ramp (from `status-colors.ts` → `tokens.css`, do NOT re-decide):**

| State | Token | Color | Label |
|-------|-------|-------|-------|
| running / in-progress | `--accent-running` (= `--color-accent`) | blue `oklch(0.62 0.14 248)` | "Running" / "In progress" |
| waiting | `--accent-waiting` | amber `oklch(0.66 0.15 60)` | "Waiting for you" |
| exited (clean) | `--accent-finished` | green `oklch(0.6 0.13 150)` | "Finished" |
| stopped / not_started | `--accent-idle` | slate `oklch(0.64 0.02 260)` | "Stopped" / "Idle" |
| error | `--accent-error` (= `--color-danger`) | red `oklch(0.58 0.16 25)` | "Error" |

**Tint washes:** Use `color-mix(in oklch, var(--accent-waiting) ~8%, transparent)` for the D-09 amber row wash, and `color-mix(in oklch, var(--color-danger) ~8%, transparent)` for the D-15 danger menu-item hover (precedent: `terminal.css` L186/195/557). Exact wash strength tuned through the ui-lab loop (Discretion).

**60/30/10 read:** The warm-white rail/inactive rows dominate (~60%); white surface cards + lines for the active row and recipe cards are the secondary surface (~30%); status accents + amber + the one blue ▶ fill are the ~10% spent only on "which session is active" and "which agent needs me."

## Copywriting Contract

The sidebar shows few words — most identity is the user's own session name/icon/cwd. The copy this phase OWNS is the status vocabulary, the section labels, and the secondary-line composition. (Empty-state and error-card copy belong to Phase 13 / are existing — out of scope here.)

| Element | Copy |
|---------|------|
| Primary CTA (inactive recipe row) | `▶` Start — circular ghost button, always visible (D-13); icon-only, `aria-label="Start session"` (a11y) |
| Hover-reveal control — edit | `✎` icon-only, `aria-label="Rename session"` (a11y — keyboard/SR equivalent of the hover-reveal control) |
| Hover-reveal control — close | `✕` icon-only, `aria-label="Close session"` (a11y — keyboard/SR equivalent of the hover-reveal control) |
| Section label — live | `WORKING AREA · {n}` (small-caps, count appended — D-12) |
| Section label — dormant | `INACTIVE · {n}` (small-caps, count appended — D-12) |
| Status word — running | `Running` (or `In progress` when agent overlay active) |
| Status word — waiting | `Waiting for you` (the highest-attention secondary line; static, no animation — D-09) |
| Status word — exited | `Finished` |
| Status word — stopped / idle | `Stopped` / `Idle` |
| Status word — error | `Error` |
| Secondary line — live row | `{statusWord} · {cwdTail}` (cwd shown as last path segment, truncated; status-only if no cwd — D-03) |
| Secondary line — recipe card | `{startupCommand}` (the recipe's essence) → fallback `{cwdTail}` → fallback `{statusWord}` (D-03) |
| Collapsed rail tooltip | `{name} · {statusLabel}` (existing `.rail-tooltip` content — unchanged) |
| Destructive — Remove (live, configured) | Context-menu item `Remove`, styled in the danger ramp `--color-danger` (D-15); confirmation handled by the existing single `ConfirmModal` (removeMode) — no new copy this phase |
| Destructive — Delete (dormant / ephemeral) | Context-menu item `Delete`, danger ramp (D-15); existing `ConfirmModal` flow — unchanged |

**Empty states (NOT this phase):** the "no sessions yet" WelcomeEmptyState restyle and the empty-Inactive-section behavior are unchanged — empty Inactive section stays unrendered (06.1 behavior). Empty/loading/error STATE DESIGN is Phase 13 (UI-05). No new empty/error copy is authored here.

**Copy discipline:** All user-controlled strings (name, cwdTail, startupCommand) render as React text nodes (auto-escaped). No `dangerouslySetInnerHTML`, no HTML interpolation (RESEARCH Security Domain V7).

## Interaction Contract

This phase is presentation-only; behavior is frozen, but the visual STATES of interaction are specified here (the sidebar's own reveal affordances — the app-wide hover/focus/active sweep is Phase 13).

| Interaction | Visual contract |
|-------------|-----------------|
| Active row | Filled `--surface` card + `--line` border + `--shadow-pop` lift + 3–4px left edge bar in the status `--accent` (D-05/D-06). Unmistakable at a glance (SC1). |
| Waiting row (active OR not) | Amber left edge bar + light amber tint wash + secondary line = "Waiting for you" (D-09). Static, no pulse. |
| Hover-reveal controls | edit ✎ (`aria-label="Rename session"`) / close ✕ (`aria-label="Close session"`) float over the row's right end at `opacity:0 → 1` on `:hover` AND `:focus-visible` (keyboard a11y required — D-02). No reserved width. Compositor-friendly transition (`opacity` only). |
| Always-visible control | The inactive recipe `▶ Start` is EXEMPT from the hover-reveal (always shown — D-13/6.1 D-06). start-no-cmd + Delete follow the hover-reveal policy. |
| Drag-to-reorder | dnd-kit `PointerSensor` 5px activation (click-to-switch preserved) + `KeyboardSensor`; one SortableContext spans both buckets; dragging row keeps its lift/opacity state. Re-verify feel after ~40% taller rows (RESEARCH Pitfall 5). |
| Collapsed rail | Active tile = filled/lifted + status-color edge bar on the rail's left; waiting tile mirrors amber edge bar; status dot enlarged to ~10px bottom-right with a thicker `--surface` ring (D-07/D-10). No whole-tile status tint. |
| Context menu | Opens at the cursor, CLAMPED to the viewport so it never overlaps the sidebar header (D-14 — `clampToViewport(x,y,w,h,vw,vh,margin)`). Remove/Delete items in the danger ramp (D-15). |

**Motion:** Only compositor-friendly properties (`opacity`, `transform`, `box-shadow`, `background`) at `--duration-fast` (120ms) `--ease-standard`. The waiting treatment is explicitly static (no animation — D-09). No layout-bound property animation (web/performance.md).

**Keep-alive guard (Core Value):** Collapse and all restyle touch ONLY `.sidebar` — `.session-view` / `.viewport-stack` visibility is untouched (Phase-4 anti-pattern guard). Click-to-switch, Cmd/Ctrl+1-9 + Shift+[/] keyboard switching, and terminal keep-alive must not regress (SC4). `EXPECTED_API_KEYS` stays 20 — no bridge change.

**Selector contract (frozen-or-update-in-lockstep):** `.sidebar-row[data-session-id]`, `.sidebar-row.active`, `.row-name`, `.collapsed-status-dot.status-dot`, `.rail-tooltip`, the `working-area` / `inactive-list` container testids, and every `data-testid` control (start-session, restart-session, start-no-cmd-session, edit-session, close-session, delete-session, sidebar-collapse, open-preferences, add-session) must survive the markup restructure or be updated with their tests in the same plan (RESEARCH Pitfall 1, Rule-1 discipline).
