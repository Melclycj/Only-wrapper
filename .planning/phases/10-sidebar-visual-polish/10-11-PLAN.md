<objective>
Close GAP-10-G: the active sidebar row crushes a medium-length session name because its Edit ✎ + Close ✕ controls are PERMANENTLY revealed (52px reserved). The 10-09 `assertNameNotCrushed` machine check caught this on `sidebar-populated` — "Parlour Claude" measured scrollWidth=98 > clientWidth=51 with rowClass='sidebar-row active', no hover, no focus-within.

Root cause (evidence-backed, from 10-VERIFICATION.md GAP-10-G): `src/renderer/sidebar.css` includes `.sidebar-row.active` in the control-REVEAL selector groups (line 186 for the `.row-controls` container gap/margin restore; line 247 for the per-`.row-control` max-width:24px/border restore). The GAP-10-A fix (10-05) and the gutter compaction (10-08) reclaimed control width ONLY in the non-active/rest state. The active row's 52px was never reclaimed.

This is not merely a fix — it restores the LOCKED design contract. **CONTEXT.md D-02 and 10-UI-SPEC.md §Interaction Contract both state controls are hover/keyboard-focus-revealed only, "including the active row", with NO reserved width.** The current implementation violates D-02 for the active row specifically.

Fix direction (operator's attempt-2 verdict is the authority; executor + orchestrator concur): let the active row's controls collapse to zero reserved width like the rest state and reveal on hover/focus-within — DO NOT exempt the active row in the fixture, DO NOT relax the 10-09 machine check.

Purpose: Make a medium name render in full on the active row so the 10-10 gate's `UI_LAB_TAG=<tag> npm run ui:shots:fresh` completes 11/11 surfaces with `assertNameNotCrushed` passing. This unblocks UI-02's closing gate.

Output: A single CSS edit to `src/renderer/sidebar.css` removing the active row from the two control-reveal selector groups, preserving hover/focus reachability and all WR-04 / collapsed-rail / dormant-exemption rules.
</objective>
