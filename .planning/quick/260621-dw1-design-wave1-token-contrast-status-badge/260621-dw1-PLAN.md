# Quick Task — Design Audit Wave 1: token / contrast / status-badge pass

Driven manually (gsd-sdk CLI not installed in this env; mirrors the `.planning/quick/`
convention of the prior 260605-ki7 task). Clears the 3 **visible** P0s from the whole-app
design audit in one low-risk foundation pass. No `src/` logic touched — design tokens + one
CSS rule only.

## Scope (EXACTLY these 3 — no creep)

### P0-A — write the missing `.status-badge` / `.status-dot` CSS
`.status-badge` had **no** CSS rule (only comments at terminal-area.css:175,362); bare
`.status-dot` was styled **only** under `.sidebar-row .row-secondary .status-dot`
(sidebar.css:156). So the badge in `IdentityHeader.tsx:89` and `IdleCard.tsx:60` rendered as
colorless run-in text with a zero-size dot — the entire status ramp died at the card.
**Fix:** add a status-pill + dot rule **scoped to the two real consumers**
(`.identity-header` + `.idle-card-identity`) so the sidebar's own dot rules stay untouched.
Both components already set inline `--accent` (the status color from status-colors.ts).

### P0-B — fix 2 WCAG-AA contrast failures (computed, not guessed — see contrast-check.mjs)
| Token | before | after | white/text contrast |
|---|---|---|---|
| `--color-accent` | oklch(0.62 0.14 248) | oklch(0.55 0.15 248) | 3.62 → **4.83** ✅ |
| `--color-accent-strong` | oklch(0.58 0.14 248) | oklch(0.51 0.15 248) | hover, darker |
| `--ink-faint` | oklch(0.66 0.01 75) | oklch(0.55 0.012 75) | 3.11 → **~4.85** ✅ |

Darkening `--ink-faint` (vs rerouting consumers) fixes every faint-text use at once and keeps
a 3-step ink gap (ink 0.32 / ink-soft 0.5 / ink-faint 0.55). `--ink-soft` left as-is (6.0:1).

### P0-C — decouple running-status blue from interactive accent
`--accent-running: var(--color-accent)` made "running" === "clickable". Set it to its own
explicit `oklch(0.62 0.14 248)` (original bright blue) so after P0-B darkens the interactive
accent, the two blues are distinct tokens + distinguishable. (Re-hue to cyan = Wave 4 option.)
